BundleMaker v2.2.0 - 한국어 사용 설명서

==================================================
1. 프로그램 개요
==================================================

BundleMaker는 여러 파일로 이루어진 프로젝트를 하나의 bundle.txt로 묶고,
수정된 번들을 실제 프로젝트에 반영하며,
적용 결과를 검증하고 필요 시 복구할 수 있도록 만든 Python CLI 도구입니다.

특히 생성형 AI 또는 LLM을 활용해 멀티 파일 프로젝트를 다룰 때,
전체 문맥을 하나로 묶어 전달하고 수정 결과를 다시 안전하게 적용하기 위한 workflow를 지원합니다.

핵심 흐름은 다음과 같습니다.

프로젝트 스캔
-> bundle.txt 생성
-> 생성형 AI / LLM에 전달
-> 수정 결과를 bundle_modified.txt로 저장
-> 실제 프로젝트에 patch 적용
-> verify 검증
-> 필요 시 restore 복구


==================================================
2. 해결하려는 문제
==================================================

멀티 파일 프로젝트를 생성형 AI에 전달할 때 자주 발생하는 문제는 다음과 같습니다.

1) 일부 파일만 참고되어 전체 문맥이 끊김
2) 개발 명세서와 실제 코드가 따로 해석됨
3) 수정된 결과를 실제 프로젝트에 반영하기 번거로움
4) 잘못 반영되었을 때 되돌리기 어려움

BundleMaker는 이를 줄이기 위해 다음을 제공합니다.

- 여러 소스 파일을 하나의 bundle.txt로 통합
- 수정된 결과를 실제 프로젝트에 자동 반영
- 적용 후 verify 수행
- manifest / backup / snapshot 기반 restore 지원


==================================================
3. 주요 기능
==================================================

[1] STEP 1 - Bundle 생성
프로젝트 내부 파일들을 읽어 하나의 bundle.txt로 만듭니다.

지원 모드:
- AUTO   : 자동으로 파일을 읽어 번들 생성
- PASTE  : 사용자가 파일 내용을 직접 붙여넣어 생성
- HYBRID : 자동 읽기를 우선 사용하고 실패 시 수동 입력

[2] STEP 3 - Patch 적용
원본 bundle과 수정된 bundle을 비교하여 실제 프로젝트에 반영합니다.

지원 전략:
- SAFE   : 작은 변경과 새 파일만 적용, 삭제는 제외
- FULL   : 모든 변경 적용, 삭제 포함
- DRY RUN: 실제 수정 없이 diff 보고서만 생성

[3] VERIFY 검증
패치 후 실제 디스크 상태를 검증합니다.

- VERIFY-A : 수정 번들과 실제 디스크 파일 비교
- VERIFY-B : 프로젝트를 다시 번들링하여 수정 번들과 비교

[4] RESTORE 복구
manifest, backup, deleted snapshot을 이용해 롤백합니다.

- 기존 파일 복원
- 삭제 파일 복구
- 생성 파일 quarantine 이동
- restore verify 수행

[5] CONFIG WIZARD
.bundlemaker.json 파일을 대화형으로 생성하고 관리합니다.

설정 가능 항목:
- 포함할 확장자
- 제외할 디렉토리

4. 디렉토리 구조
==================================================

프로젝트 내부 생성물은 아래 경로에 저장됩니다.

<PROJECT_ROOT>/
  .bundlemaker/
    state/
    manifests/
    reports/
    backups/
    locks/
    quarantine/

번들 출력 파일은 현재 실행 디렉토리 기준 아래에 저장됩니다.

<CWD>/
  bundles/
    bundle.txt
    bundle_applied_<timestamp>.txt

자동 제외:
- .bundlemaker
- bundles

즉, 프로그램이 생성한 내부 파일이 다시 번들에 포함되는 문제를 막습니다.

==================================================
8. 메인 메뉴 설명
==================================================

[1] STEP 1 — Create bundle from project
프로젝트 파일을 읽어 bundle.txt를 생성합니다.

[2] STEP 3 — Apply patch from modified bundle (+VERIFY)
수정된 번들을 실제 프로젝트에 반영하고 검증합니다.

[c] Configure — create/overwrite .bundlemaker.json
설정 파일을 생성하거나 덮어씁니다.

[r] Restore — rollback from patch manifest backups
이전 patch 적용 상태를 복구합니다.

[q] Quit
프로그램을 종료합니다.


==================================================
9. 설정 파일(.bundlemaker.json) 설명
==================================================

BundleMaker는 .bundlemaker.json 파일을 통해
포함할 확장자와 제외할 디렉토리를 제어합니다.

설정 구조는 크게 두 부분으로 나뉩니다.

1) extensions
2) exclude_dirs

각각 mode에 따라 동작 방식이 달라집니다.

- default 모드
  기본 목록을 기준으로 add / remove 적용

- custom 모드
  only 목록에 있는 값만 사용


==================================================
10. 확장자 설정 방법
==================================================

확장자 설정은 두 가지 방식으로 할 수 있습니다.

방법 1) Configure 메뉴 또는 --config 사용
방법 2) .bundlemaker.json 파일 직접 수정

----------------------------------------
10-1. Wizard로 설정하기
----------------------------------------

다음 명령으로 설정 wizard를 실행할 수 있습니다.

python bundlemaker.py --config

또는 프로그램 실행 후 메뉴에서 c를 선택합니다.

Wizard에서는 다음과 같은 질문이 나옵니다.

- 기본 확장자를 사용할 것인지
- 추가할 확장자가 있는지
- 제거할 확장자가 있는지
- custom only 모드로 갈 것인지

예시 1) 기본 확장자 + md 추가
- Use DEFAULT extensions? -> Yes
- Add extensions -> md
- Remove extensions -> (비움)

이 경우 기본 확장자에 md가 추가됩니다.

예시 2) cpp, hpp만 포함
- Use DEFAULT extensions? -> No
- Select ONLY extensions to include -> cpp,hpp

이 경우 cpp와 hpp만 스캔 대상이 됩니다.

----------------------------------------
10-2. 설정 파일 직접 수정하기
----------------------------------------

예시 A) 기본 확장자 사용 + md 추가

{
  "extensions": {
    "mode": "default",
    "only": [],
    "add": ["md"],
    "remove": []
  }
}

예시 B) py, md만 포함

{
  "extensions": {
    "mode": "custom",
    "only": ["py", "md"],
    "add": [],
    "remove": []
  }
}

중요:
확장자는 점(.) 없이 적는 것이 기준입니다.
예:
- py
- md
- cpp

11. 제외 디렉토리 설정 방법
==================================================

제외 디렉토리도 확장자와 같은 방식으로 설정할 수 있습니다.

----------------------------------------
11-1. Wizard로 설정하기
----------------------------------------

예시 1) 기본 제외 디렉토리 + docs_temp 추가
- Use DEFAULT exclude dirs? -> Yes
- Add exclude dirs -> docs_temp
- Remove exclude dirs -> (비움)

예시 2) custom 모드로 tmp와 logs만 제외
- Use DEFAULT exclude dirs? -> No
- Select ONLY dirs to exclude -> tmp,logs

----------------------------------------
11-2. 설정 파일 직접 수정하기
----------------------------------------

예시 A) 기본 제외 디렉토리 + docs_temp 추가

{
  "exclude_dirs": {
    "mode": "default",
    "only": [],
    "add": ["docs_temp"],
    "remove": []
  }
}

예시 B) tmp, logs만 제외

{
  "exclude_dirs": {
    "mode": "custom",
    "only": ["tmp", "logs"],
    "add": [],
    "remove": []
  }
}

주의:
.bundlemaker 와 bundles 는 항상 하드 제외됩니다.
설정에서 제거해도 다시 스캔 대상이 되지 않습니다.


==================================================
12. STEP 1 - Bundle 생성 방법
==================================================

STEP 1은 프로젝트 파일을 읽어 bundle.txt를 만드는 단계입니다.

지원 모드:
- AUTO
- PASTE
- HYBRID

----------------------------------------
12-1. AUTO 모드
----------------------------------------

명령:
python bundlemaker.py --auto

동작:
- 프로젝트를 자동 스캔
- 허용 확장자만 읽음
- 자동 읽기가 가능한 파일을 bundle.txt에 포함
- 결과를 bundles/bundle.txt에 저장

장점:
- 가장 빠름
- 일반적인 프로젝트에 적합

----------------------------------------
12-2. PASTE 모드
----------------------------------------

명령:
python bundlemaker.py --paste

동작:
- 사용자가 각 파일 내용을 직접 붙여넣음
- 입력 종료 시 한 줄에 \END 입력

장점:
- 외부 파일 내용 직접 입력 가능
- 자동 읽기 어려운 환경에서도 사용 가능

----------------------------------------
12-3. HYBRID 모드
----------------------------------------

명령:
python bundlemaker.py --hybrid

또는 기본 실행 후 HYBRID 선택

동작:
- 우선 자동 읽기
- 실패한 파일은 수동 붙여넣기로 보완

장점:
- 편의성과 유연성의 균형

----------------------------------------
12-4. 진행 상태 저장
----------------------------------------

STEP 1 도중 중단되더라도 아래 파일에 상태가 저장됩니다.

<PROJECT_ROOT>/.bundlemaker/state/bundle_state.json

다시 실행하면 이어서 진행할 수 있습니다.

13. bundle.txt 생성 결과 예시
==================================================

bundle.txt는 대략 아래와 같은 형식을 가집니다.

=== BUNDLE GENERATED: 2026-03-09T12:34:56 ===
=== REL_ROOT: C:\project ===

=== FILE: src/main.py ===
print("hello")
=== END FILE: src/main.py ===

즉, 각 파일은 FILE / END FILE 마커로 구분됩니다.


==================================================
14. LLM에 전달하는 방법 예시
==================================================

실제 사용 시에는 bundle.txt와 master 문서(기획 문서, 개발 명세서 등)를 함께 전달할 수 있습니다.

예시 지시문:

1.bundle.txt에는 모든 코드가 들어있고 master문서(EX.개발 명세서) 에는 이 프로젝트의 기획이 담겨있다. 이 모든걸 종합적으로 꼼꼼히 확인하여 지금 코드에서 나타나는 문제점과 버그를 알려줘라

또는 수정 지시로 확장할 수도 있습니다.

예시:
- 전체 파일 기준으로 버그를 수정해줘라
- 수정된 전체 결과를 다시 bundle 형식으로 출력해줘라
- 기존 기능은 유지하고, null 처리만 보강해줘라

이후 수정 결과를 bundle_modified.txt로 저장합니다.


==================================================
15. STEP 3 - Patch 적용 방법
==================================================

명령:
python bundlemaker.py --patch

또는 프로그램 실행 후 메뉴에서 2 선택

입력:
- Original bundle path
- Modified bundle path

기본적으로 다음 파일을 많이 사용합니다.

원본:
bundles/bundle.txt

수정본:
bundle_modified.txt

그 후 patch 전략을 선택합니다.

- 1 = SAFE
- 2 = FULL
- 3 = DRY RUN

----------------------------------------
15-1. SAFE
----------------------------------------

적용 대상:
- 작은 변경
- 새 파일

적용 제외:
- 큰 폭의 변경
- 삭제

보수적으로 적용하고 싶을 때 적합합니다.

----------------------------------------
15-2. FULL
----------------------------------------

적용 대상:
- 모든 변경
- 삭제 포함

강력하지만 위험성도 큽니다.
중요한 프로젝트라면 먼저 DRY RUN 또는 SAFE를 권장합니다.

----------------------------------------
15-3. DRY RUN
----------------------------------------

실제 파일은 수정하지 않습니다.
대신 diff 보고서만 생성합니다.

사전 점검용으로 적합합니다.


==================================================
16. VERIFY 검증 설명
==================================================

PATCH 이후에는 자동으로 VERIFY가 수행됩니다.

VERIFY-A
- 수정 번들과 실제 디스크 파일 비교

VERIFY-B
- 프로젝트를 다시 번들링해 수정 번들과 비교

이 과정을 통해
"적용했다고 기록된 상태"가 아니라
"실제로 디스크가 원하는 상태인지"까지 확인할 수 있습니다.


==================================================
17. RESTORE 복구 방법
==================================================

명령:
python bundlemaker.py --restore

또는 메뉴에서 r 선택

복구 시 사용되는 정보:
- manifest
- backup_map
- deleted_snapshots
- pre_hashes

복구 과정:
1) 백업 파일 복원
2) 삭제된 파일 스냅샷 복구
3) 생성된 파일 quarantine 이동 가능
4) restore verify 수행

즉, 단순 복사 복원이 아니라 해시 기반 검증까지 포함한 복구입니다.


==================================================
18. 자동 읽기 제한과 안전 장치
==================================================

AUTO 모드에서는 다음 파일이 건너뛰어질 수 있습니다.

- 5MB 초과 파일
- 바이너리 파일
- .env, id_rsa 같은 민감한 이름
- .pem, .key, .pfx, .crt 같은 민감한 확장자

안전 장치:
- atomic write
- root 경계 검사
- path traversal 방지
- patch manifest 생성
- backup 생성
- STEP 3 lock
- verify / restore verify
- created file quarantine

즉, 단순 번들러가 아니라 적용 안정성을 고려한 설계입니다.

19. 실제 사용 예시
==================================================

----------------------------------------
예시 1) Python 프로젝트 전체를 번들로 만들기
----------------------------------------

상황:
- py 파일 위주 프로젝트
- 기본 확장자 그대로 사용

순서:
1. python bundlemaker.py --auto
2. bundles/bundle.txt 생성 확인
3. bundle.txt를 LLM에 전달
4. 수정 결과를 bundle_modified.txt로 저장
5. python bundlemaker.py --patch
6. SAFE 선택
7. verify 결과 확인

----------------------------------------
예시 2) C/C++ 프로젝트에서 cpp, hpp만 포함
----------------------------------------

상황:
- cpp, hpp만 스캔하고 싶음

방법:
1. python bundlemaker.py --config
2. extensions -> custom -> only = cpp,hpp
3. bundle 생성
4. 이후 patch / verify 수행

----------------------------------------
예시 3) Markdown 문서도 함께 묶고 싶을 때
----------------------------------------

상황:
- 코드와 함께 md 문서도 LLM에 전달하고 싶음

방법:
1. python bundlemaker.py --config
2. extensions -> default 사용
3. add -> md 입력
4. bundle 생성
5. README나 명세 문서까지 함께 bundle에 포함 가능

----------------------------------------
예시 4) 먼저 diff만 보고 싶을 때
----------------------------------------

상황:
- 수정본을 바로 적용하기 불안함

방법:
1. python bundlemaker.py --patch
2. original / modified bundle 선택
3. DRY RUN 선택
4. reports 폴더의 diff 보고서 확인

----------------------------------------
예시 5) 잘못 적용되어 원래대로 돌리고 싶을 때
----------------------------------------

상황:
- patch 후 결과가 마음에 들지 않음

방법:
1. python bundlemaker.py --restore
2. manifest 선택
3. 복구 진행
4. restore verify 결과 확인

20. 권장 사용 순서
==================================================

가장 추천하는 순서는 다음과 같습니다.

1) Configure로 설정 확인
2) bundle 생성

- 먼저 DRY RUN
- 그다음 SAFE
